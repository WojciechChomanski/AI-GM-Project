# Breath Weapon and Armour Item Contract v1.0

Generated by `python scripts/foundry_export.py` from `rules/weapons.json`, `rules/weapon_stances.json`,
`rules/weapon_maneuvers.json` and `rules/armors.json`. Re-run the script after any rules change; a test fails if the
committed export is stale.

## Weapon item (`weapons_items.json`, item_kind = Weapon)
- **Identity:** weapon_id, weapon_label, weapon_type, source_file, contract_version.
- **Numbers:** base_damage, stamina_cost, min_str, weight, durability.
- **Damage:**
  - damage_type: the primary type, one of slashing / piercing / blunt
  - damage_types: comma list
  - armor_defeat: 0 for swords, 1 for impact weapons
  - percussive: 0/1
  - features: point / beak / hook / chain
- **Guards:**
  - guard_set
  - default_guard
  - guards: comma list; `offensive,neutral,defensive` when the weapon has no guard set
  - guard_change_stamina: 1
  - guards_json: per guard, its type, attack, defence, initiative and stamina
- **Maneuvers:**
  - maneuvers: comma list, already filtered by the weapon's features
  - maneuvers_json: full effects

## Armour item (`armor_items.json`, item_kind = Armor)
armor_tier, armor_variant, armor_label, armor_slashing, armor_piercing, armor_blunt, rigid, coverage, stamina_penalty,
weight, max_durability.

## Sheet fields the actor needs (to add in CSB)
- **Text, current state:** `current_guard`, `previous_guard`, `chosen_maneuver`, `aimed_zone`, `attack_damage_type`.
- **Hidden JSON text fields, stored between attacks:** `conditions_json`, `fight_state_json`.
- **Per-family mastery uses and perk picks:** `mastery_json`, the same dict as `character.progression`.

## Gaps the repo cannot close
- **No engine inside CSB:** CSB formulas cannot run the Python engine. A full attack (one maneuver choice, armour by zone and type, conditions) must go through `POST /combat/attack` (scripts/combat_engine.py), via a macro or the GM console. A pure-CSB roll can only show the guard's attack/defence numbers and the maneuver's attack bonus.
- **Not built yet:** the actor template, item templates and macro do not exist in the repo yet. They have to be built in the Foundry world, as with the Class items (see IMPORT.md).
- **Stale names:** existing Foundry items made before this contract will not have the new fields.
